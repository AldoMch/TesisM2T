# L1 correspondence v2

L1 now measures reference correspondence using a validated semantic alignment. The former `l1_ged_accuracy` calculation was a fixed-alignment discrepancy count rather than an optimized GED. It is replaced by `l1_structural_similarity`; old GED columns are not populated with the new score.

## Definitions

- `l1_node_coverage`: fraction of reference entities whose responsibilities are covered, from a complete independent reference-side scan.
- `l1_gen_precision`: fraction of generated entities corresponding to reference concepts, from a complete independent generated-side scan. An absent reference counterpart does not by itself imply hallucination.
- `l1_edge_precision`, `l1_edge_recall`, `l1_edge_f1`: two-sided directed edge correspondence. Each side has its own numerator, so split/merge mappings may cover different numbers of edges on each side.
- `l1_boundary_accuracy`: group-weighted layer agreement. The field name is retained for compatibility; the manuscript calls it Layer agreement.
- `l1_structural_similarity`: `100 * (1 - D/Z)`, where `D` is the sum of unmatched reference entities, unmatched generated entities, unmatched reference edges, unmatched generated edges, and inconsistent matched groups. `Z` is the total number of entities, comparable edges, and matched groups. All item weights are one.

A zero denominator is `None`/blank, never an invented perfect score. Edge F1 is undefined if both comparable edge sets are empty and zero if exactly one is empty. Group layer agreement is undefined when no group is matched.

## Graph scope

Pure `package`, `folder`, and `frame` declarations retain hierarchy paths but are not scored entities. Other supported declarations, including composite entities and ports, remain eligible. This is an explicit declaration-based convention, not a claim that every rectangle is semantically a component. C4 entity and boundary macros are handled equivalently.

Arrowheads determine direction; a bidirectional arrow gives two edges. Repeated ordered endpoint pairs collapse regardless of labels. Unoriented links, annotation/layout links, and directed edges incident to grouping containers are counted separately. No ancestor fallback or reachability-based matching is used.

Edges between distinct members of one accepted split/merge group are excluded on both sides from edge correspondence. Explicit self-edges remain comparable. All exclusions have output counts.

## Alignment and cache validation

Two independent node scans must cover every eligible entity exactly once, with real booleans and legal supporting identifiers. Supporting groups must be disjoint, nonempty, and 1:1, 1:N, or N:1. Compatible repeated proposals are consolidated; ambiguous or invalid proposals require another judge response. Node scans are not derived from group membership.

The judge uses the configured `gpt-5.4-mini` service with temperature 0, structured JSON output, and compact node IDs that are resolved back to exact paths locally. Failed schema/group validation is retained for audit and retried, including focused group repair when the independent scans are valid. Invalid alignments never receive correspondence scores.

The new cache name is `judge_alignment_v2_<model>.json`. A fingerprint covers the protocol version, prompt, requirements context, and candidate paths. The model identity is also checked. Legacy caches are not silently treated as v2 caches. Existing generated files, legacy scores, and L2 results are preserved.

## Running the evaluator

This document describes the underlying v2 entity alignment and edge rules.
The published main results use the hierarchy-aware edge revision described in
[L1_HIERARCHY_OFFLINE.md](L1_HIERARCHY_OFFLINE.md). The saved scores are in
`Results/l1.csv`.

For fresh evaluation, use the command in [README.md](README.md). The general
batch evaluator retains the v2 edge rules; apply the hierarchy-aware offline
step before comparing fresh results with the published main study. API-backed
judgments require explicit credentials and a selected model. The historical
rendering batch used PlantUML 1.2026.2.

## Validation

```powershell
python -B -m unittest evaluation_script.tests.test_evaluation_core evaluation_script.tests.test_l1_revision evaluation_script.tests.test_l1_hierarchy -q
```

The regression tests cover split/merge edge coverage, reverse arrows, duplicate invariance, directionality, exclusion of pure grouping nodes, absence of ancestor/reachability shortcuts, empty-set behavior, independent scans, malformed alignments, layer weighting, and stale caches.
